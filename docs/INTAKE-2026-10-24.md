## Gaps found in the core flow

1. **No assignment to a project exists.** A task has no project field (`text, due, state, sourceEntryIds, …`); the
   `project` field lives only on widget records. Nothing records that P1–P7 belong to planner or C1–C3 to Cardloft, so
   the project cards cannot show them and a repo session cannot pull them.
2. **Cardloft is not a connected project.** The three project widgets are planner, planner-data (switched off) and
   threejs-engine-dev. The owner's own task C1 is this gap, and it is also why Cardloft items cannot reach its card.
3. **Shipped work does not close its task.** P1, P2, P3, P4 and P5 shipped 10-16 (#174, #175) and are still open on 10-24, 8 days later. The bridge
   reads repo state out to cards (merges, issues) but nothing reads a merge back to the task that asked for it.
4. **Typed tasks skip the notes path.** 12 of 23 tasks have no source note: 5 planner-feedback tasks, all 4 Cardloft
   tasks (one is typed twice) and 3 finance or test tasks. No model run ever saw them, so nothing asked which project they belong to.
5. **Project work never entered assessment.** 50 assessments over 17 runs covered 20 entries (about 2.5 passes each), and
   the 18 questions went to chores, finance and the horizon-spec notes. The planner and Cardloft items skipped it (gap 4).
6. **Overdue is unverified.** Two finance tasks due 10-14 and 10-15 are still open in the export. Whether the Summary flags
   them is not checked here; check it on the app before treating this as a gap.
7. **No live read path for an agent.** The nightly export has never landed a commit (R6, A11), so a session can reach
   notes only through a manual export. This is what the live protocol replaces.
